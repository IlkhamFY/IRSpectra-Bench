\subsection{Blind protocol}
\label{si:protocol}

\subsubsection{Solver contract}

Each IRSpectra-Bench item is a four-field JSON object. The solver sees
\emph{only}
\begin{center}
\texttt{\{qid, formula, ir\_bands\_cm-1, h\_nmr, c\_nmr\}}.
\end{center}
No name, SMILES, InChIKey, scaffold, atom-type hint, retrieved spectrum,
licence stamp, or PMC id enters the prompt
(Listing~\mainref{lst:payload}{1}, adapted from one IRexp record).
Gold constitution is scored offline by the InChIKey-14 indicator
(\S\ref{si:eqs}).

Difficulty is declared \emph{a priori} by RDKit ring analysis:
\emph{simple} iff $\leq$2 rings, no fused/spiro/bridgehead system,
$\leq$22 heavy atoms; else \emph{complex}.
The $n{=}500$ headline is near-50/50 (248/252);
the eligible IRexp corpus is 17.5\% simple / 82.5\% complex.
Corpus-reweighted extras on a validate-clean subset are in
\S\ref{si:extras} and are not $n{=}500$ headline numbers.

\subsubsection{Frozen roster}

The code release records the frozen roster and the expand-500 campaign.

\begin{itemize}
  \item $n{=}500$ roster: frozen \texttt{qid} lists in the code release.
        Sampler seeds for early draws were not captured; the released
        roster is fixed and reusable but not exactly re-drawable.
  \item expand-500 campaign: 115/115 simple/complex; seed 2026500;
        0 collisions with any prior round.
        Six $^{13}$C-overread flags known \emph{before} any solve:
        R26, R31, R102, R105, R107, R138.
\end{itemize}

\subsubsection{Stopping and pooling}
\label{si:stopping}

\begin{itemize}
  \item The $n{=}500$ roster is a pre-specified frozen \texttt{qid} list,
        not an outcome-selected subset.
  \item Gold keys for the expand-500 arm were used only for local scoring
        and are not in the review copy.
  \item Official expand-500 chamfer is $103/230$ verify vs $129/230$ self
        (\S\ref{si:fverify}); confidence intervals were not computed on
        that arm.
\end{itemize}

\subsubsection{Allowed tools}

RDKit formula / parse check only. No web search. No retrieved spectrum.
The pooled $n{=}500$ headline mixes no-thinking runs with the thinking-tier
expand-500 cut (200 of 500).
The two harnesses are not interchangeable; scoring is the same InChIKey-14 contract.

A deposit is JSONL of \texttt{\{qid, candidates: [SMILES,\ldots]\}} under a
stated budget. Headline budget: $\leq 3$ ranked SMILES per \texttt{qid}.
Self-ranking and forward-verified re-ranking are reported separately.

\subsection{Scoring identities}
\label{si:eqs}

The identities in this section restate main-text Eqs.~\mainref{eq:factor}{1}, \mainref{eq:ik14}{2}, \mainref{eq:metrics}{3}, and \mainref{eq:chamfer}{4}.
The pool estimator (Eq.~\ref{si:eq:pool}) is not in the main text.

A candidate $\hat y$ matches gold $y^\star$ at constitution iff
\begin{equation}
\label{si:eq:ik14}
s(\hat y, y^\star)
=\mathbf{1}\big[\mathrm{IK}_{14}(\hat y)=\mathrm{IK}_{14}(y^\star)\big].
\end{equation}
$\mathrm{IK}_{14}$ is the first 14 characters of the RDKit InChIKey
(connectivity layer). Full stereo-sensitive InChIKey is reported only on
validate-clean $n{=}295$ (\S\ref{si:extras}).

With ranked pool $\mathcal{C}_i=(c_{i1},\ldots,c_{ik})$, $k\leq 3$,
\begin{align}
\label{si:eq:top1}
\mathrm{top\text{-}1}
&=\frac1n\sum_i s(c_{i1}, y_i^\star),\\
\label{si:eq:recall}
\mathrm{recall}@k
&=\frac1n\sum_i \mathbf{1}\big[\exists\,j\leq k:\; s(c_{ij}, y_i^\star)=1\big],\\
\label{si:eq:prec}
\mathrm{prec.}|\mathrm{recall}
&=\frac{\sum_i s(c_{i1}, y_i^\star)}{\sum_i \mathbf{1}[y_i^\star\in\mathcal{C}_i]}.
\end{align}
These are the three reportable numbers. They factorise as
\begin{equation}
\label{si:eq:factor}
\mathrm{top\text{-}1}
=(\mathrm{recall}@k)\times(\mathrm{prec.}|\mathrm{recall})
\end{equation}
when the same pool is used for both stages. The rates have different
denominators and must not be differenced.
Self-ranking $\mathrm{prec.}|\mathrm{recall}$ on $n{=}500$ is $227/249$
(91.2\%), which is not forward-verify precision.

Forward-verify re-ranks by symmetric chamfer on $^{13}$C peak sets
$P,Q\subset\mathbb{R}$
\begin{equation}
\label{si:eq:chamfer}
d(P,Q)
=\frac1{|P|}\sum_{p\in P}\min_{q\in Q}|p-q|
+\frac1{|Q|}\sum_{q\in Q}\min_{p\in P}|q-p|,
\end{equation}
where $\hat P(c)$ is predicted \emph{blind} to the observed list $P_{\mathrm{obs}}$.
An instrumented diagnostic on a protocol slice is $58/65$
(\S\ref{si:fverify}).
The $n{=}500$ forward-verify diagnostic is $204/45/251$
(\S\ref{si:fverify}).
The expand-500 official arm score is $103/230$ verify vs $129/230$ self
(\S\ref{si:fverify}).

A pool estimator on an index set $\mathcal{S}$ is
\begin{equation}
\label{si:eq:pool}
\hat p_{\mathcal{S}}
=\frac{1}{|\mathcal{S}|}\sum_{i\in\mathcal{S}} s(c_{i1}, y_i^\star).
\end{equation}
The paper headline uses $\mathcal{S}$ of size 500 (frozen \texttt{qid} list).
The $n{=}519$ \texttt{score\_pooled.py} print ($243/519$) is not used.

Confidence intervals on earlier validate-clean subsets are bootstrap
95\% (\texttt{score\_main.boot}, seed 0, 2000 resamples).
Paired model differences use McNemar with Holm correction.
Confidence intervals are not reported for $n{=}500$ or expand-500.

\subsubsection{Headline prompt}

The headline Claude wrapper was not captured
(main text, Experimental setup and Limitations).
Only the per-compound four-field payload is released.
The skeleton below is the contract, not a recovered verbatim system prompt.

\begin{lstlisting}[style=prompt]
You are given only:
  formula          (as from HRMS)
  ir_bands_cm-1    (author-transcribed experimental list)
  h_nmr, c_nmr     (printed shift lists)
Return <= 3 ranked SMILES.
No name, no SMILES hint, no scaffold, no retrieved spectrum.
Check molecular formula with RDKit before emitting a candidate.
\end{lstlisting}

The solver-facing fields of Listing~\mainref{lst:payload}{1} are
\texttt{formula}, \texttt{ir\_bands\_cm-1}, \texttt{h\_nmr}, and
\texttt{c\_nmr}.
SMILES, InChIKey, and licence fields in that record are not part of the prompt.

\subsubsection{Forward-verify prompt}

For each candidate SMILES, predict a $^{13}$C peak list without seeing
the observed list.
Re-rank by chamfer distance (Eq.~\ref{si:eq:chamfer}).
The instruction dispatched to the forward-prediction step was
not captured; only the candidate SMILES and the resulting
numeric lists are on disk for the protocol slice.

\subsubsection{Cross-vendor harness}

Verbatim prompts in the code release are the cross-vendor
harness prompts, not the missing headline Claude wrapper.
External submissions must document model version, prompt, and tool access
(\texttt{docs/LEADERBOARD.md}).

\subsection{Offline peak-list baseline (NMRTrans)}
\label{si:nmrtrans}

NMRTrans (Yang et al., KDD 2026; arXiv:2602.10158;
code commit \texttt{9a72756}; checkpoint
\texttt{little1d/C-H-Formula}, file
\texttt{nmrtrans-c-h-nmr-formula.ckpt}, 499/499 weights loaded)
is a set transformer with a T5-small decoder.
It reads a molecular formula and unordered $^1$H and $^{13}$C peak sets.
It has no IR channel.
This run is offline CPU inference, beam size 3, no sampling, and no paid API.
Questions are the frozen $n{=}500$ roster
(spectro-agent \texttt{48fcd30}).
Gold is a unique match of formula, IR bands, and the $^{13}$C string
into \texttt{irexp\_resolved} (500/500, none ambiguous).
The generator did not see SMILES or InChIKeys.
Scoring is RDKit InChIKey-14.
No confidence intervals.

Printed lists only.
A $^1$H range becomes a midpoint and a half-width; a single shift has
half-width 0.
Multiplicity is mapped onto the model's split vocabulary; unknown
patterns stay at the unknown index (87 peaks).
Printed integrals and $J$ values are copied.
76 of 4,298 proton peaks had no printed integral; those values were
stored as 0 and were not filled in as 1H.
A $^{13}$C shift is repeated only when the list prints an $n$C count;
the model treats that repeat as its intensity channel.
Nineteen shifts outside $[0,220]$ ppm were clamped by the published
$/220$ normalisation.
Nine formulae contain Se or Sn, which the released 12-element formula
vector drops.
IR bands were not passed in.

\subsection{Closed-Book Harness}
\label{si:closed-book}

The closed-book harness is the operational form of the Blind protocol
(\S\ref{si:protocol}).
Each solver call receives only the four-field peak-list payload
\texttt{\{qid, formula, ir\_bands\_cm-1, h\_nmr, c\_nmr\}}:
no compound name, SMILES, InChIKey, scaffold hint, retrieved spectrum, or web search.
The only tool is an RDKit formula / parse check before a candidate is emitted.

The $n{=}500$ headline uses Claude Opus 5 on a consumer harness.
Thinking-tier mix matches the model card (\S\ref{si:card}): earlier rows
without thinking; the expand-500 cut (200 of 500) on the thinking tier.
Each deposit holds at most three ranked SMILES; scoring is RDKit InChIKey-14
as in \S\ref{si:eqs}.
The cross-vendor $n{=}60$ arm reuses the same payload with vendor-specific
prompts in the code release.

What was not recorded is unchanged from the model card and Reproducibility
(\S\ref{si:repro}): headline wrapper text, model snapshots, temperature, and
sampler seeds.
Frozen deposits are the intended reproducibility claim, not bit-exact
re-inference.
