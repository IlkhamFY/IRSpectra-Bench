\section{Blind protocol}
\label{si:protocol}

\subsection{Solver contract}

Each IRSpectra-Bench item is a four-field JSON object. The solver sees
\emph{only}
\begin{center}
\texttt{\{qid, formula, ir\_bands\_cm-1, h\_nmr, c\_nmr\}}.
\end{center}
No name, SMILES, InChIKey, scaffold, atom-type hint, retrieved spectrum,
licence stamp, or PMC id enters the prompt
(main-text Listing~1, adapted from one IRexp record).
Gold constitution is scored offline by the InChIKey-14 indicator
(\S\ref{si:eqs}).

Difficulty is declared \emph{a priori} by RDKit ring analysis:
\emph{simple} iff $\leq$2 rings, no fused/spiro/bridgehead system,
$\leq$22 heavy atoms; else \emph{complex}.
The $n{=}500$ headline is near-50/50 (248/252);
the eligible IRexp corpus is 17.5\% simple / 82.5\% complex.
Corpus-reweighted extras on a validate-clean subset are in
\S\ref{si:extras} and are not $n{=}500$ figures.

\subsection{Pre-registration}

The code release records the frozen roster and the expand-500 campaign.

\begin{itemize}
  \item $n{=}500$ roster: frozen \texttt{qid} lists in the code release.
        Sampler seeds for early draws were not captured; the released
        roster is fixed and reusable but not exactly re-drawable.
  \item expand-500 campaign: 115/115 simple/complex; seed 2026500;
        0 collisions with any prior round.
        Six $^{13}$C-overread flags known \emph{before} any solve:
        R26, R31, R102, R105, R107, R138.
\end{itemize}

\subsection{Stopping and pooling}

\begin{itemize}
  \item The $n{=}500$ roster is a pre-specified frozen \texttt{qid} list,
        not an outcome-selected subset.
  \item Gold keys for the expand-500 arm were used only for local scoring
        and are not in the review copy.
  \item Official expand-500 chamfer is $103/230$ verify vs $129/230$ self
        (\S\ref{si:fverify}); confidence intervals were not computed on
        that arm.
\end{itemize}

\subsection{Allowed tools}

RDKit formula / parse check only. No web search. No retrieved spectrum.
No thinking tier on the core protocol.
A thinking-tier consumer arm is labelled as such in the score notes and
is not interchangeable with the no-thinking protocol.

A deposit is JSONL of \texttt{\{qid, candidates: [SMILES,\ldots]\}} under a
stated budget. Headline budget: $\leq 3$ ranked SMILES per \texttt{qid}.
Self-ranking and forward-verified re-ranking are reported separately.

\section{Scoring identities}
\label{si:eqs}

These identities match main-text Eqs.~(1)--(7).

A candidate $\hat y$ matches gold $y^\star$ at constitution iff
\begin{equation}
\label{si:eq:ik14}
s(\hat y, y^\star)
=\mathbf{1}\big[\mathrm{IK}_{14}(\hat y)=\mathrm{IK}_{14}(y^\star)\big].
\end{equation}
$\mathrm{IK}_{14}$ is the first 14 characters of the RDKit InChIKey
(connectivity layer). Full stereo-sensitive InChIKey is reported only on
validate-clean $n{=}295$ (\S\ref{si:extras}).

With ranked pool $\mathcal{C}_i=(c_{i1},\ldots,c_{ik})$, $k\leq 3$,
\begin{align}
\label{si:eq:top1}
\mathrm{top\text{-}1}
&=\frac1n\sum_i s(c_{i1}, y_i^\star),\\
\label{si:eq:recall}
\mathrm{recall}@k
&=\frac1n\sum_i \mathbf{1}\big[\exists\,j\leq k:\; s(c_{ij}, y_i^\star)=1\big],\\
\label{si:eq:prec}
\mathrm{prec.}|\mathrm{recall}
&=\frac{\sum_i s(c_{i1}, y_i^\star)}{\sum_i \mathbf{1}[y_i^\star\in\mathcal{C}_i]}.
\end{align}
These are the three reportable numbers. They factorise as
\begin{equation}
\label{si:eq:factor}
\mathrm{top\text{-}1}
=(\mathrm{recall}@k)\times(\mathrm{prec.}|\mathrm{recall})
\end{equation}
when the same pool is used for both stages. The rates have different
denominators and must not be differenced.
Self-ranking $\mathrm{prec.}|\mathrm{recall}$ on $n{=}500$ is $227/249$
(91.2\%), which is not forward-verify precision.

Forward-verify re-ranks by symmetric chamfer on $^{13}$C peak sets
$P,Q\subset\mathbb{R}$
\begin{equation}
\label{si:eq:chamfer}
d(P,Q)
=\frac1{|P|}\sum_{p\in P}\min_{q\in Q}|p-q|
+\frac1{|Q|}\sum_{q\in Q}\min_{p\in P}|q-p|,
\end{equation}
where $\hat P(c)$ is predicted \emph{blind} to the observed list $P_{\mathrm{obs}}$.
An instrumented diagnostic on a protocol slice is $58/65$
(\S\ref{si:fverify}).
The $n{=}500$ forward-verify wall is $204/45/251$
(\S\ref{si:fverify}; \texttt{data/fverify\_n500/WALL\_n500.md}).
The expand-500 official arm score is $103/230$ verify vs $129/230$ self
(\S\ref{si:fverify}).

A pool estimator on an index set $\mathcal{S}$ is
\begin{equation}
\label{si:eq:pool}
\hat p_{\mathcal{S}}
=\frac{1}{|\mathcal{S}|}\sum_{i\in\mathcal{S}} s(c_{i1}, y_i^\star).
\end{equation}
The ICLR headline uses $\mathcal{S}$ of size 500 (frozen \texttt{qid} list).
The $n{=}519$ \texttt{score\_pooled.py} print ($243/519$) is not used.

Confidence intervals on earlier validate-clean subsets are bootstrap
95\% (\texttt{score\_main.boot}, seed 0, 2000 resamples).
Paired model differences use McNemar with Holm correction.
Confidence intervals are not reported for $n{=}500$ or expand-500.

Outcomes perfectly nested (McNemar $p{=}0.001$).

\paragraph{Generate-wide (60-compound arm).}
Ten solver agents, up to six candidates each, pooled then re-ranked:
recall $32\%\to 42\%$, top-1 $23\%\to 30\%$
(McNemar $p{=}0.34$); verification precision falls $84\%\to72\%$.

\paragraph{IRexp-fine-tuned generator (locked slice).}
Pooled with Claude: recall $33.5\%\to54.1\%$, top-1 $28.4\%\to35.1\%$
(McNemar $p{=}0.015$).
Training is the intervention that has been observed to move
$P(\mathrm{true}\in\mathrm{pool})$.

\paragraph{Battery-electrolyte subset.}
$n{=}46$ literature electrolyte chemistry (not operando): 26\% top-1,
recall-bound.

\paragraph{Four-model Claude ladder ($n{=}24$).}
Haiku $\subset$ Sonnet $\subset$ Opus $\subset$ Fable is
capability-sensitive but underpowered for adjacent ranks, with a
protocol asymmetry.

\paragraph{Difficulty variation.}
Pre-registered draws differ in difficulty.
The headline remains $n{=}500$ (Eq.~\ref{si:eq:pool}).

\subsection{Headline prompt}

Wrapping instruction text was not captured on the headline Claude arm
(main-text Limitations~(i)).
Only the per-compound four-field payload is released.
The skeleton below is the contract, not a recovered verbatim system prompt.

\begin{lstlisting}[style=prompt]
You are given only:
  formula          (as from HRMS)
  ir_bands_cm-1    (author-transcribed experimental list)
  h_nmr, c_nmr     (printed shift lists)
Return <= 3 ranked SMILES.
No name, no SMILES hint, no scaffold, no retrieved spectrum.
Check molecular formula with RDKit before emitting a candidate.
\end{lstlisting}

\subsection{Forward-verify prompt}

For each candidate SMILES, predict a $^{13}$C peak list \emph{without}
seeing the observed list. Re-rank by $d(\hat P(c), P_{\mathrm{obs}})$
(Eq.~\ref{si:eq:chamfer}).
The instruction dispatched to the forward-prediction sub-agents was
not captured; only the candidate SMILES and the resulting
numeric lists are on disk for the protocol slice.

\subsection{Cross-vendor harness}

Verbatim prompts in the code release (ESI S2) are the cross-vendor
harness prompts, not the missing headline Claude wrapper.
External submissions must document model version, prompt, and tool access
(\texttt{docs/LEADERBOARD.md}).
